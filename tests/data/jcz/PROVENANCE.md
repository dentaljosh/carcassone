# Vendored JCloisterZone reference data — provenance

Reference tile data for the **differential tile oracle**
(`tests/test_jcz_tile_oracle.py`). Nothing here is engine code; it is a
*second, independent* description of the same 32 base-game tile kinds, used to
certify `engine/wingedsheep/carcassonne/tile_sets/base_deck.py`.

## `jcz_basic_5x.xml`

| | |
|---|---|
| upstream repo | `farin/JCloisterZone-Client` (the JCZ 5.x **client**, not the engine repo — the engine reads XML handed to it by the caller and ships none) |
| upstream path | `src/extraResources/expansions/basic.xml` |
| upstream ref | `master`, fetched 2026-08-03 |
| raw URL | https://raw.githubusercontent.com/farin/JCloisterZone-Client/master/src/extraResources/expansions/basic.xml |

| license | JCloisterZone is AGPL-3.0; this is a data file vendored verbatim for test-oracle purposes |

**Bytes are verbatim upstream** — deliberately *not* annotated with an inline
provenance header, so the copy stays sha256-comparable against upstream. The
sha256 above is pinned in `tests/test_jcz_tile_oracle.py`
(`test_vendored_reference_is_the_pinned_bytes`); an accidental edit fails there
rather than silently weakening the oracle.

The tile-set used is `basic:2` — the C3 base game with the 8 garden
("flowers") variants substituted in place, which is the exact edition
`base_deck.py` models. Verified: the deck-count multiset matches ours 32/32
kinds, 72/72 tiles.

The README link in the *engine* repo
(`JCloisterZone/master/src/main/resources/tile-definitions/`) is **stale — it
404s**. The 4.x branch still carries an older copy under a different
(`<pack>`/`<farm>`, pre-garden) schema if a second opinion is ever wanted.

## `TILE_MAPPING.tsv`

Generated by `measurement/jcz_spike_20260803/jcz_tile_diff.py` on 2026-08-03 and
checked in as the **pinned expectation** for the 32-kind pairing (our kind ↔ JCZ
id ↔ deck count ↔ resolved rotation). The oracle re-derives the pairing from
scratch every run and asserts it equals this table, so a silent re-pairing
cannot mask a field-data divergence.
