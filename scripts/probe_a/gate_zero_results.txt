VERDICT
==========================================================================
  Key facts:
    - The tiny per-component head is NOT the bottleneck (numpy 8,365 ns = 0.28x; torch 26,280 ns = 0.88x). Both clear 3x with room.
    - The bottleneck is the DECOMPOSITION. The Cython baseline computes it in C for free;
      pure-Python flat_leaf.decompose() costs 404,574 ns = 13.5x the WHOLE compiled leaf.
    - Memoization does NOT rescue PATH-PY: even reusing 96% of component VALUES, you still
      must decompose() the child board to KNOW which components changed -> 13.6x. FAIL.

  Component-identity keying (open-question 1): FEASIBLE. Components key
  stably on their member-position frozensets (Decomp.city_root_positions /
  road_root_positions / farm_root_keys) — invariant sets, ~96% reused per
  placement. But stable keys only save the HEAD eval, not the decompose.

  ==> MARGINAL / CONDITIONAL PASS.
      The structured v_leaf clears <=3x ONLY via PATH-CY (1.28x): emit the
      per-component features from the Cython leaf's existing C decomposition and run
      the head (numpy or torch) on top. This is NOT the spec's drop-in `decompose()`
      + head — it requires extending flat_leaf_cy to return per-component features
      (bounded, ~1 day of Cython work). The naive Python drop-in (PATH-PY, 13.8x)
      and the memo lever (13.6x) both FAIL the budget outright.
