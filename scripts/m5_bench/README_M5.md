# M5 bench — run book

**Status: BUILT + LOCALLY VERIFIED (Linux, k1×32), NOT YET RUN ON THE M5.**
Generated by `scripts/m5_bench/build_bundle.py`. Everything under this directory is a
build artefact — edit `scripts/m5_bench/*` in the repo and re-run the builder, never
edit here.

Two independent benches live here:

| | what it measures | deps | must work? |
|---|---|---|---|
| `bench_champion.py` | single-stream **s/move** of the production champion | numpy, pyyaml (+ optional Cython) | **yes** |
| `bench_ane_forward.py` | batch-1 **net-forward ms** of the CL-067 net, CPU vs ANE | torch, coremltools | no — best effort |

The champion's play path is pure Python + numpy + pyyaml: **no torch, no Rust, no
orchestrator**. That is why it can be shipped as a directory and run anywhere.

```bash
rsync -a --info=progress2 \
    --exclude '.venv/' --exclude 'results/' --exclude '__pycache__/' \
    --exclude 'bundle/build/' --exclude 'bundle/carcassonne_ai/*.so' \
    --exclude 'bundle/carcassonne_ai/*.c' \
    /mnt/c/carc-shared/m5_bench_20260728/ \
    <user>@100.64.175.108:~/m5_bench_20260728/
```

≈31 MB, almost all of it the optional CL-067 checkpoint — add `--exclude 'bundle/net/'`
and it is under 1 MB.

**The excludes are not optional.** The share copy has a Linux x86-64 `.venv` and
Linux `.so` files from the local verification run; copying either to the Mac would
give you a venv that cannot run and — far worse — an `.so` that fails to load while
`cython.leaf_active` reports honestly but the setup script's "built" claim does not.
`setup_m5.sh` creates a fresh arm64 venv and compiles fresh arm64 extensions.

## 1. Setup — THE FIRST COMMAND TO RUN

```bash
ssh <user>@100.64.175.108 'bash ~/m5_bench_20260728/setup_m5.sh'
```

⚠️ `setup_m5.sh` resolves its own directory from `$BASH_SOURCE`, so it does **not**
depend on the remote shell's starting directory — safe under the project's
"Claude Code drops `cd` in SSH" rule (CLAUDE.md). Every command below is likewise
absolute.

What it does, in order:

1. finds a `python3` ≥ 3.10 (fails loudly with the `brew install python@3.12` fix);
2. creates `~/m5_bench_20260728/.venv` and installs **numpy + pyyaml** — deliberately a
   *fresh* venv, because an editable `carcassonne_ai` install anywhere would shadow the
   bundle and silently bench the wrong tree;
3. **optionally** `pip install cython` and builds `flat_leaf_cy` / `flat_repr_cy`
   natively for arm64 (`bundle/setup_cy.py build_ext --inplace`). **This step is allowed
   to fail** — both call sites fall back to pure Python, which is *correct*, just ~2×
   slower per leaf. Log: `cython_build.log`. If it fails for want of a compiler:
   `xcode-select --install`, then re-run `setup_m5.sh`.
4. proves the bundle imports standalone with `PYTHONPATH` cleared, and constructs the
   champion with `verify=True` — the factory checks the leaf's curve *values*, its
   *outputs* on real boards, and three hash dialects, and **raises** on any mismatch.
   So a green setup means the bundle runs the champion of record
   (`governance/PRODUCTION.yaml` → `puct_priors_v29_bmild_cap8`, leaf `a36d2e15a3b3d71d`).

Runtime: ~1–2 min (mostly pip). Add `--no-cython` to skip step 3.

## 3. The full ladder

```bash
ssh <user>@100.64.175.108 'nohup ~/m5_bench_20260728/.venv/bin/python -u ~/m5_bench_20260728/bench_champion.py > ~/m5_bench_20260728/bench.log 2>&1 &'
```

Budgets, in order: **k1×32 · k4×172 · k4×344 · k4×688**. Only the last is the champion
of record (`PRODUCTION.yaml` `fair_deploy`: k_dets 4 × sims_per_det 688 = 2752
sims/move); the three below it are the same *width* at ¹⁄₁₆, ¼ and ½ depth, so the
ladder isolates depth cost and doubles as a Pareto sanity check.

**Runtime: ~6 min for one pass** (extrapolated from the local k1×32 rung and
cross-checked against the Pixel's measured 1.7 s/move at k4×688 — see §5). That is far
short of the 20–60 min originally assumed, so **prefer `--repeat 3`** (~18 min): it
builds each rung's p90 from 180 samples instead of 60, at a wall-clock cost that is
still trivial.

The result JSON is rewritten atomically after **every** budget, so it is harvestable
live and a killed run still yields the completed rungs.

Output: `results/bench_champion_<host>_<stamp>.json`, carrying

* per-budget `overall` and `by_phase` mean / p50 / p90 / min / max s/move,
* every individual sample (`pos_id`, phase, `k_remaining`, `n_legal`, seconds),
* `cython.leaf_active` + `cython.leaf_path` — **read this before comparing any two
  machines**; Cython vs pure Python was **4.5×** on the local control below, so a
  compiler-less M5 is not comparable to a Cython 5900XT,
* `machine` (CPU brand, P/E core counts, RAM, OS),
* `agent_manifest` — the factory's runtime-verified manifest (leaf hashes, value panel,
  search knobs), i.e. the resolved config, not a label,
* `resolved_env` — the production leaf knobs as they stood the instant before
  `carcassonne_ai` was first imported.

Useful flags: `--repeat 3` (tighter means), `--limit 20` (shorter), `-v` (per-position
lines), `--tag "m5 idle"`.

### What would count as the unified-memory hypothesis firing

The comparison of interest is **s/move at k4×688 on the M5 vs the 5900X**, with
`cython.leaf_active` equal on both sides. The champion's hot path is
`flat_leaf.decompose` + union-find bookkeeping over Python dicts/sets — pointer-chasing,
DRAM-latency-bound, which is exactly the shape a unified-memory part could win on.
Prior anchors, for orientation only (different boxes, different conditions — do not
treat as a controlled baseline):

* Pixel 9 Pro, on-device app, k4×688: **1.7 s/move**
  (`measurement/ANDROID_WALLCLOCK_MEMO_20260728.md`).
* Contended desktop during the same memo's probe: ≈2× the phone.

## 4. The ANE probe (optional, run last)

```bash
ssh <user>@100.64.175.108 '~/m5_bench_20260728/.venv/bin/pip install torch coremltools'
ssh <user>@100.64.175.108 '~/m5_bench_20260728/.venv/bin/python ~/m5_bench_20260728/bench_ane_forward.py'
```

Loads the bundled **CL-067** checkpoint (`bundle/net/distill_iter_03.pt`, sha256 verified
at build time against `measurement/distill_strong_20260723/CHECKPOINT_MANIFEST.json`),
times a batch-1 torch CPU forward, then converts to CoreML `mlprogram` and times
`CPU_ONLY` / `CPU_AND_NE` / `ALL`. Runtime ~2–4 min, most of it conversion.

`--precision fp16` (default) is what the ANE actually runs; `--precision fp32` is the
honest apples-to-apples against the torch CPU baseline. Run both if the gap looks large.

**Why batch-1 and not a throughput number:** CL-067's deployability was refuted on cost —
the deployed evaluator is `make_remote_single_evaluator` (k=1 per request) and the worker
*blocks*, so a deployed agent gets no batching and pays full per-forward latency. The
claim's close-out puts the requirement at **~4× cheaper per move**. A batch-1 forward is
the atom of that. This measures latency only; it is **not** a strength or deployability
verdict, and nothing here touches the champion or `PRODUCTION.yaml`.

If torch/coremltools will not install, the script prints the exact `pip install` line and
exits — the champion bench (§3) is unaffected and is the deliverable that matters.

## 5. Local reference numbers

Measured on the local 5900XT box with **this exact bundle and these exact 60 positions**,
so the M5 numbers are directly comparable rung-for-rung. Full detail, provenance and the
ladder extrapolation: [LOCAL_REFERENCE.md](LOCAL_REFERENCE.md).

| budget | sims/move | leaf path | mean s/move | p50 | p90 | n |
|---|---|---|---|---|---|---|
| k1×32 | 32 | Cython | **0.0403** | 0.0372 | 0.0634 | 58 |
| k4×172 / k4×344 / k4×688 | | | *not run locally* — the box was busy | | | |

By phase at k1×32: **meeples 0.0443** vs **tiles 0.0364** s/move — the meeple half costs
more despite choosing among far fewer actions, independently reproducing
`measurement/ANDROID_WALLCLOCK_MEMO_20260728.md` §2 on a different box at a different
budget. `exact_latches: 0`.

Cython vs pure Python, same 6 positions, same box: **0.036 vs 0.164 s/move = 4.5×**.

⚠️ **The local box was LOADED** — the CL-067 equal-wall-clock gate was live throughout
(16 workers, loadavg ~13 on 32 threads). These figures are **pessimistic** for the
5900XT and are a code-works reference, not its clean single-stream number. A quiet-window
5900XT rerun is owed before any M5-vs-5900XT claim is made.

| `carcassonne_ai/*.pyx` | `src/carcassonne_ai` | sources for the optional native build |
| `wingedsheep/**` | `engine/wingedsheep` | minus the tkinter visualiser and the tile art |
| `endgame_solver.py`, `c5_leaf_override.py`, `snapshot.py` | `scripts/{level2,classical_search,measurement_infra}` | bundled **top-level** because that is exactly how the library imports them |
| `setup_cy.py` | generated | optional in-place arm64 Cython build |
| `positions.jsonl` | `measurement/champ_action_logs/champ_games.jsonl` | 60 mid-game roots the champion itself reached |
| `net/*.pt` | `/mnt/c/carc-shared/distill_strong_20260723/ckpt/` | CL-067 iter_03, sha256-verified |

### About the positions

60 roots in `root_replay` form — `(deck_seed, action_prefix)`, which is **lossless for
any policy** because the engine consumes the global `random` stream in exactly one place
(the deck shuffle in `get_init_board`). See
`scripts/measurement_infra/root_replay.py`. They are drawn from the champion's own
449-game action-log corpus, so every position is a board the production champion
actually reached, and:

* **all have `k_remaining > 2`**, asserted at harvest AND re-checked at bench time —
  the fair agent latches its exact endgame solver at `k_remaining ≤ 2`, and a solve is a
  wildly different (and highly variable) cost from a PIMC search. `exact_latches` in the
  output must read **0**; anything else is flagged loudly in the JSON.
* **all have ≥2 legal actions** — a forced move is not a decision.
* **30 tile-phase / 30 meeple-phase.** The Android wall-clock memo (§2) found the meeple
  half costs *more* than the tile half despite choosing among far fewer actions, so a
  tile-only sample would understate s/move. `by_phase` in the output keeps the two
  separable.
