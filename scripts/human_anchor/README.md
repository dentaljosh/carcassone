# Phase 4 — human-anchor infrastructure

Code for the **human-anchor** program: measure the champion against real
strong/expert humans (the only non-saturated reference that gates the
superhuman goal — see `docs/MEASUREMENT_FIRST_SPEC_2026-06-18.md`). Recruiting
humans is Joshua's job; this is the CODE that makes their play measurable.

Everything here only **reads/imports** the sweep-shared modules
(`endgame_solver.py`, `mcts.py`, `flat_leaf.py`, `virtual_score_v2.py`,
`game_wrapper.py`, `fair_agent.py`) — it never edits them.

Locked scope: **2-player, Base + Farmers** (the engine enforces it; the harness
asserts `state.players == 2`).

## Files

| file | role |
|---|---|
| `env_preamble.py` | production leaf env (cap 8, v2.9 meeple curve, FLAT_LEAF, net-on-CPU). `import`ed FIRST by every script so the agent + solver use the exact production leaf. |
| `_common.py` | shared helpers: position reconstruction, board renderer, action description, git-rev / leaf-hash / signature. |
| `build_suite.py` | **4.1** expert-position suite builder + renderer + scorer (+ self-test). |
| `play_harness.py` | **4.2** logged human-vs-agent play harness with signed manifests (+ self-test). |
| `luck_floor.py` | **4.3** luck-floor variance decomposition -> `measurement/human_anchor/LUCK_FLOOR.md`. |

## 4.1 — expert-position suite (`build_suite.py`)

Produces a JSONL suite of 200-500 positions, each with provenance
(`deck_seed` + [`actions`] + `ply`, replayable via `root_replay` /
`gen_endgame_positions.replay_to`), a stratum tag, and a ground truth:

- **exact (K≤4):** the exact-solver `child_values` (objective per-action values
  ⇒ objective regret). K=2 comes FREE from the on-disk cache
  `measurement/pre_tool_audit/k2_childvalues.jsonl`; K=3/4 are generated by
  CALLING `endgame_solver.solve()` — **CPU-heavy, needs boxes**, guarded behind
  `--generate --run-solver`, resumable per gen_id.
- **midgame (non-exact):** stratified positions (farm fights, meeple scarcity,
  merges / closure races, generic) labeled by the strongest available search
  (champion clairvoyant HeuristicMCTS @ h6400) → best move + per-action root Q.
  Also heavy (search), guarded.

This **same suite is the Phase-5 analyzer's held-out validation set** (a
move-quality analyzer must reproduce the exact/search regret ranking).

```bash
.venv/bin/python scripts/human_anchor/build_suite.py --self-test          # RUNS (proves the pipeline)
.venv/bin/python scripts/human_anchor/build_suite.py --from-cache --out measurement/human_anchor/suite_exact_k2.jsonl
.venv/bin/python scripts/human_anchor/build_suite.py --render --suite <suite.jsonl>
.venv/bin/python scripts/human_anchor/build_suite.py --score  --suite <suite.jsonl> --choices <human.json>
# NEEDS BOXES (heavy): K=3/4 exact solves
.venv/bin/python scripts/human_anchor/build_suite.py --generate --run-solver --ks 3 4 --out measurement/human_anchor/suite.jsonl
```

`--choices` is a JSON `{position_id: chosen_action_id}`. The scorer emits
per-stratum mean regret (objective points for exact, leaf-Q for midgame) and a
best-move match rate.

**Stratum proxies** (heuristic, documented in `classify_stratum`):
`meeple_scarcity` = a side has ≤1 free meeple · `farm_fight` = ≥3 farmers
committed · `closure_race` = ≥100 tiles placed with a live city meeple ·
`midgame_generic` otherwise · `endgame_k{K}` = K≤4 (tagged upstream).

## 4.2 — logged play harness (`play_harness.py`)

Human (or agent) vs the production **FairHeuristicMCTSAgent** — the
audited-honest (Phase 0.1/0.4 green), non-clairvoyant PIMC + K≤2
marginalized-exact-endgame champion. Records every action with per-move agent
telemetry (path pimc/exact/forced, latch_k, solver secs/nodes, wall ms/ts) and
a **signed manifest** (agent version = git rev, resolved leaf env, config hash,
leaf hash, deck seed + hash, result, tamper-evident content signature). No ELO
math. Supports seat-swapped paired-deck rematches (`--paired`).

```bash
.venv/bin/python scripts/human_anchor/play_harness.py --self-test          # RUNS one fair-vs-fair game + rematch
.venv/bin/python scripts/human_anchor/play_harness.py --human 0 --sims 400 --k-dets 4 --seed 12345 \
    --out measurement/human_anchor/games
```

## 4.3 — luck floor (`luck_floor.py`)

Pure LIGHT analysis over the on-disk seat-swap paired archives
(`/mnt/c/carc-shared/*/seed*_a{0,1}.json`): decomposes margin variance into a
deck-luck share vs a play/skill share, and sizes the human program (ceiling
win-rate vs an expert + games needed to power a superhuman claim). Writes
`measurement/human_anchor/LUCK_FLOOR.md`.

```bash
.venv/bin/python scripts/human_anchor/luck_floor.py
```

## What still needs boxes

- **4.1 full generation** (`--generate --run-solver`): the K=3/4 exact solves and
  the h6400 midgame labeling are CPU-heavy. The K=2 exact records (`--from-cache`)
  and the self-tests run locally with no solver/boxes.
- A tighter luck-floor ceiling wants a **solver-vs-h6400 full-game** win-rate
  (Phase-3 K≤4 `child_values` cache); the `exact_*_clair__vs__heur3200` hybrids
  are the current best proxy.
