# Foundational audit — 2026-06-02 (6-agent parallel sweep)

Triggered after discovering the MCTS never modeled chance (clairvoyant single-determinization
on the true deck). Goal: find every OTHER elementary/foundational gap that caps superhuman
strength by construction. 6 parallel audit agents, one per domain. **Multiple agents converged
independently on the same root causes** (high confidence). Two live correctness bugs were
independently re-verified in the code by the main thread.

Bottom line: it was never the randomness (we deleted it via clairvoyance). We failed because of
a STACK of foundational issues + 2 live bugs, all masked by a hand-crafted leaf good enough to
hide them.

---

## TIER 1 — Live correctness bugs (verified in code, corrupt training data)

### F-A1 [BLOCKER] Farm scoring double-counts cities → corrupted REWARD + v2.7 leaf
`engine/wingedsheep/carcassonne/utils/points_collector.py:284-299` (`count_farm_points`):
`cities: Set[City] = set()` then `cities.union(CityUtil.find_cities(...))` once per farmer
connection. `City` (objects/city.py) has **no `__eq__`/`__hash__`** → set dedups by IDENTITY,
and `find_cities` returns fresh `City` objects per call → a field touching one finished city
from N farmer connections scores **N×3 instead of 3**.
- Agent-measured (150 random games): **153/883 scored farms (17%) wrong**, 825 spurious pts,
  worst single farm **+69** (one city counted 24×). Asymmetric → does NOT cancel in score-diff.
- Corrupts (a) the true terminal reward (`count_final_scores`→`get_game_ended`) AND (b) the base
  `virtual_score` → the dominant term of the v2.7 search leaf.
- The v2.7 closure path dedups correctly by `frozenset(city.city_positions)` (virtual_score_v2.py:348)
  — proof the right semantics were known and missed here. SEPARATE from the 2026-05-29 connectivity fix.
- **Fix:** dedup by `frozenset(city_positions)` in `count_farm_points`; add `__eq__/__hash__` to City.
  Then RE-SWEEP v2.7 caps (CAP=12, drop-3-open) — scoring-bug fixes shift hyperparam optima.

### F-A2 [BLOCKER] MCTS transposition double-counts visits → corrupted POLICY targets
`mcts.py` keys nodes by board `state_key`, children by action via `self._nodes.setdefault(...)`
then `parent.children[action]=child`. A rotationally-symmetric tile (straight road, etc.) placed
at one position emits ≥2 "legal" rotations producing the IDENTICAL board → both action slots point
at the SAME node. `root_visit_distribution`/`select_for_training` (mcts.py:455-505) build the policy
target as `[children[a].N for a in actions]` → that move's full visit count appears in BOTH slots
→ ~2× mass inflation.
- Agent-measured: **24/120 (20%)** decision nodes have ≥1 collision; verified `id()` identical and
  sum(child.N)=2×root.N at a real River-opening node. Affects NeuralMCTS AND HeuristicMCTS.
- Distorts EVERY self-play policy target (toward symmetric-placement moves) + `best_action` in eval.
- **Fix:** AlphaZero edge/node split (per-edge N/W; nodes shared only for value), OR dedup actions
  mapping to the same child when building the visit distribution. Re-sweep c_puct/FPU after (F-D-FPU).

## TIER 2 — Architectural caps (why the learned value can't beat the heuristic; agents converged)

### F-B1 [BLOCKER] The value head is never in the search loop → can't bootstrap past v2.7
Production self-play runs `leaf_eval=v2_5` (run_selfplay_iter.py:276) → `make_v25_value_wrapper`
replaces the net value with the v2.7 leaf at EVERY MCTS leaf. So the policy target is generated by
a tree evaluated entirely by the heuristic; the value head is a passive side-regression onto final
outcomes, never driving search, never on its own inference distribution. There is no feedback by
which a better value head improves its own data → it can never exceed the teacher. Strong form of
the "calibration cliff." **Fix:** run ≥1 full self-play→train→eval cycle with `leaf_eval=nn`
(value head drives search, value_blend ramped), or train value on deep-search root-Q (nn-leaf)
targets, not just final score.

### F-B2 [BLOCKER] Clairvoyant search + train/serve info mismatch (the original finding)
No chance nodes; search descends the true future deck (mcts.py:18,365). Teacher (search) sees future
draws; student (net, fair inputs) cannot → value labels encode unlearnable information; floor on
value error set by deck entropy the teacher didn't pay. Also inflates all strength numbers
(clairvoyant-vs-clairvoyant). `fair_chance=True` exists but is single-determinization (not an
expectation) and unwired in production. **SCREEN RESULT (2026-06-02, n=76, iter_11, sims=200/c=3):
clairvoyant vs fair = 36W/40L = 0.474 match score (−0.5σ) = DEAD EVEN.** → future-sight is NOT
load-bearing for SEARCH STRENGTH; our +180 numbers are NOT clairvoyance-inflated (validity intact).
So the chance problem bites via VALUE-LEARNING (single-future high-variance targets + net can't see
the bag, F-B3), NOT via search strength. **De-prioritizes the exact-chance-node rebuild as a strength
lever** — it's a value-target-quality fix, behind the TIER-1 bugs + F-B1/F-B3.
**Caveat F-B2b [MAJOR]:** `fair_chance` reshuffle is unsound vs the transposition table — deck order
isn't in the state key, so determinized children with different futures merge. Fix before trusting
any non-clairvoyant search (add deck-order/seed to key, or real chance nodes).

### F-B3 [BLOCKER] Representation blind to farm connectivity (+ MAJOR: bag composition)
- Net sees farmers as corner-presence bits (board_repr.py:296-304) but has NO channel for the
  field-merge graph or which cities each field borders. A 3×3-kernel/6-block conv (~13-cell
  receptive field) CANNOT reconstruct board-spanning farm topology. Net is structurally blind to
  the highest-value, highest-variance scoring axis → can't beat the v2.7 leaf, which computes it via
  `FarmUtil.find_farm` flood-fill. Farm-control scalars exist (features.py:44-101) but are OFF in
  both production global-best checkpoints (10 scalars, not 12).
- **Bag composition [MAJOR]:** only a scalar `tiles_remaining/85` (features.py:118); NO per-tile-type
  remaining-count vector anywhere. The net cannot represent draw-expectation or tile-counting even in
  principle. Bag is exactly known by deduction.
- **Open-feature completion progress [MAJOR]:** no channel for city open-edge count / monastery
  neighbor count → closure odds not locally derivable for large features.
- **Fix:** add live feature-ownership/connectivity INPUT planes (infra exists in aux_targets.py —
  currently training-only) + a bag histogram (~24 types). Turn on farm scalars at minimum.

## TIER 3 — Data / training quality (caps efficiency & monotonic improvement)

- **F-C1 [MAJOR] No symmetry augmentation** (BACKLOG-known, never actioned): zero rot/flip aug →
  ~4× (rotation) free data unused. Representable (centered window has no fixed global orientation);
  needs rotate_board_repr_90 + rotate_action; works on existing .npz, no scratch retrain. Defer
  reflection (curved roads aren't reflection-symmetric).
- **F-C2 [MAJOR] Saturated value target:** `tanh((p0-p1)/15)` pins to ±1 for typical 30-80pt margins
  → MSE on a saturated target kills mid-range calibration exactly where close games live. Widen norm
  (/40) or switch to W/L + BCE; re-derive the 0.61 corr reference. (selfplay.py:300, train_iter.py:359)
- **F-C3 [MAJOR] Advisory gate → chain random-walks:** `run_pathb_cluster_loop.sh` warm-froms the
  literal previous iter unconditionally (line 277); the anchor gate is "advisory only" (line 311),
  never used to keep/reject. A noisy/regressed iter is silently accepted and parents the next 9.
  **Fix:** accept iter N only if it beats best-so-far at verdict-n vs the fixed ref (confirm machinery
  at line 140 already exists); else warm-from best-so-far.
- **F-C4 [MAJOR] Thin exploration:** dirichlet_alpha=0.3 vs measured ~0.53 (mcts.py docstring/BACKLOG);
  temp_threshold=15 plies ≈ 7-8 placements of ~80 → τ=1 covers only the opening; fixed-River opening
  already narrows distribution → overfit-to-own-narrow-play (the lineage-overfit failure). A/B at n≥100.
- **F-C5 [MINOR] Silent window-overflow drops:** WindowOverflowError bucketed as generic "failed"
  (run_selfplay_iter.py:319); the promised >0.5% overflow metric (DECISIONS) was never implemented.
  Stronger play sprawls more → may overflow more than the random-validated <1%. Instrument it.
- **F-C6 [MINOR] Two value currencies:** selfplay uses literal `15.0` (selfplay.py:300); engine uses
  `SCORE_NORM_SCALE` (game_wrapper.py:50). Currently equal; unguarded against drift. Use one symbol.

## Reframe of "why we failed"
Not the randomness — we deleted it. The learned value (the engine of AlphaZero) was (1) never in the
search loop, (2) trained by a clairvoyant teacher it can't imitate, (3) on a corrupted reward (farm
bug) and corrupted policy targets (transposition bug), (4) through a representation blind to farms and
the bag, (5) on un-augmented, narrow, saturated-target data, (6) in a loop that doesn't even keep the
good iterations. The v2.7 leaf was good enough to mask all of it at strong-amateur.
