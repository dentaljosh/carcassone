## 1. The question, and why it is asked TONIGHT

The 2026-07-29 promotion made **k8×1376 = 11008** the champion of record. It was chosen as
the **cheapest point on a plateau**, not as a peak: `governance/PRODUCTION.yaml`
`budget_authorized_by` (2) cites `results.csv curve_k16x1376_22016_vs_deploy_k4x688`
(n=196, band 48e9) at **+35.58 / z 2.68** versus the 4× point's **+49.85 / z 3.48** —
"statistically the same place", so 8× was called strictly dominated.

That reasoning is only as good as the ruler. Two things make it worth re-asking with a
different instrument:

- **The plateau may be the ruler, not the search.** This is exactly the H1-vs-H2 fork
  CL-070 was built for, and the oracle pilot already resolved it **one rung down**: at
  2752-vs-11008 the flat elo curve was NOT convergence — the deeper pick was genuinely
  better (+0.7375 pts/disagreement, cluster-robust z +2.97,
  [ORACLE_PILOT_EXT_READOUT](ORACLE_PILOT_EXT_READOUT_20260728.md) §5). If the same is
  true one rung up, "11008 is at the knee" is a statement about the yardstick.
- **Head-to-heads are currently suspect.** A 3σ cross-band contradiction on the cliff rows
  means a between-band elo comparison can be read two ways. This instrument has **no
  opponent, no elo, no bands and no ruler compression** — roots are replayed and worlds
  are CRN-derived — so it sidesteps that entirely.

**THE QUESTION.** On the positions where the champion (11008) and 2× budget (22016)
choose DIFFERENT moves, does the 22016 pick score better?

**Sign convention, fixed here and never re-read:** **positive = the 22016 (wider) pick
scores better**, in engine points, root-player POV, averaged over the same M CRN worlds.

**WHAT THIS CANNOT BE.** Not a promotion candidate, not a deploy lever, not an elo cell,
no `results.csv` row, `PRODUCTION.yaml` untouched. 22016 costs 2× the champion's clock and
CL-068 / [TOURNAMENT_TIMING](../../docs/research/TOURNAMENT_TIMING_2026-07-26.md) are not
in question. This buys **understanding of where the strength curve actually ends**, which
is a measurement-program question (structural blocker #1), not a deploy one.

## 3. The cost trick — one k16 run yields BOTH picks

Naively a cell costs 11008 + 22016 = 33024 sims. **It costs 22016**, because arm A is a
world-PREFIX of arm B. Three facts, each read off `fair_agent._pimc_move`:

1. Worlds come from ONE stream — `det_rng = random.Random(det_seed_base(move_idx) + 1)`,
   consumed by `k_dets` sequential `reshuffled_determinization` calls. `det_seed_base`
   depends on (agent seed, move_idx) only: **not** on `k_dets`, **not** on sims.
2. World *i*'s search seed is `base + 100 + i` — also `k_dets`-independent.
3. Pooling is `_merge_root_stats` in world order 0..k−1, and the eligibility floor
   `min_pooled_visits = DEFAULT_MIN_POOLED_VISITS = 2` is a **constant**, not a function
   of k or budget.

(1)+(2) ⇒ the k16 agent's worlds 0..7 **are** the k8 agent's worlds. (3) ⇒ pooling the
first 8 reproduces the k8 accumulators through the same `+=` sequence, so even the
order-sensitive float addition matches, and the same rule reads the same action. This is
the k-parallel split's own "KEY LOGICAL STEP" argument (`PRODUCTION.yaml`) applied along
**k** instead of across processes.

⚠️ **PROVEN PER RUN, NOT ASSERTED.** `--verify-agent-parity N` builds REAL
`FairHeuristicPriorAgent`s at k8×1376 and k16×1376 on the same root with the same seed,
calls the **deployed** `_pimc_move`, and asserts both equal the prefix-8 and full-16 picks.
A mismatch fails the cell loudly. **≥20 cells will carry the proof.** If parity fails, the
run is void and the design reverts to 33024 sims/cell.

Additional fidelity note: this harness does not *mirror* the deployed search, it **calls**
it — each world goes through `fair_agent.search_one_world` and pools through
`fair_agent._merge_root_stats`, the same two functions `_pimc_move` calls. (CL-070's probe
mirrors `_pimc_move` with a raw `NeuralMCTS` because it needs mid-search snapshots at 7
levels; here one level suffices, so the real thing can be called directly.) A construction
guard refuses to run if `_meeple_dedup` / `_intra_reuse` / `_parallel_workers` are on.

## 4. The judge — and why oracle-sims stays at 100

Judge (unchanged from the validated pilot): **clairvoyant-PUCT continuation, M=32
CRN-paired deck completions, `--oracle-sims 100`**, value = the TERMINAL engine score
margin after playing the afterstate out with the continuation policy on BOTH seats.

The obvious objection is that 100 sims/move is *far below* the 22016 it is judging, and
that this is worse than the pilot's 100-vs-11008. **The objection misreads what the judge
does.** Read the harness (`_playout_value`): the judge never searches for a better move
than the candidates and never scores an afterstate with its own search value. It applies
each pick to the SAME determinized world, plays BOTH out under the SAME continuation
policy with the SAME seed, and returns the engine's own terminal `state.scores`
differential. What it needs is **playout quality good enough that a better afterstate
converts into more points**, not depth matching the candidate. Depth-matching would be a
category error: a 22016-sim judge would be a *stronger continuation*, which is a different
axis from *being a valid comparator*.

Three reasons to hold it at 100, stated so they can be held against the result:

1. **COMPARABILITY IS THE DELIVERABLE.** The whole point is to place the 11008→22016 step
   on the SAME ruler as the pilot's 2752→11008 step (+0.7375). Changing the judge changes
   the ruler and makes the two steps incommensurable — and the *contrast between the two
   steps* is what answers "is there room above 11008", far more than either absolute.
2. **The bias is common-mode under CRN.** The two afterstates differ by ONE move at a
   shared root and are played out in the same world with the same seed, so a weak
   continuation's error is largely differenced away. That is the pilot's §6.2 argument and
   it does not weaken as the candidate deepens — the judge was already 27×–110× below the
   candidates, and 220× is not a change in kind.
3. **n is the binding constraint, not judge depth.** The expected effect here is SMALLER
   than the pilot's (§5). Doubling `--oracle-sims` roughly doubles scoring cost and
   therefore halves the achievable n at fixed wall-clock — spending the budget on the
   thing that is *not* the limiter.

⚠️ **THE HONEST CAVEAT.** This is a judgement call, and it is the design's main soft spot.
A weak continuation may systematically under-convert exactly the kind of small positional
edge that a 2× budget buys, which would bias the measured effect TOWARD ZERO — i.e. toward
the "11008 is at the knee" conclusion. **So a NULL result here is the weaker of the two
outcomes and must be reported as "not detected on this instrument", never as "there is
nothing above 11008".** A POSITIVE result is not vulnerable to this direction.

**Two named, pre-registered, NOT-RUN-TONIGHT follow-ups** (deliberately reserved, per the
pilot's own precedent of pre-naming its discriminator):
- **`--oracle-sims` sensitivity**: re-score a nested subset at 400. Addresses the
  weak-continuation threat (§6.2) only — the family is unchanged, so it is NOT a
  self-preference discriminator.
- **Out-of-family SIGN check**: re-score a nested subset with
  `--oracle-policy tier1-greedy`. Addresses same-family self-preference. **SIGN ONLY,
  never magnitude** — the Tier-1 judge is ~1.83× noisier and carries its own bias.

## 5. Sample size, and the ADAPTIVE RULE (fixed here, in advance)

**Power arithmetic.** The pilot measured, on this instrument at M=32, per-position
sd = **2.406 pts** and cluster-robust se = **0.2486** at n=100 (design effect 1.067, since
only 11 of 89 roots carried a second record).

The 11008→22016 step should be **smaller** than 2752→11008: the budget ratio is 2× rather
than 4×, and it sits further along a curve everything else says is flattening. Taking
**half** the pilot's effect as the planning value (+0.37 pts):

> n needed for z = 2 at effect 0.37 and sd 2.406: n ≥ (2 × 2.406 / 0.37)² ≈ **169**;
> × design effect 1.07 ≈ **181**. **TARGET n = 200 scored disagreements** ⇒ z ≈ 2.2 if the
> effect is exactly half, z ≈ 4.3 if it is undiminished, and a null at n=200 bounds the
> effect to roughly < +0.34 (upper 95%).

**Cells needed.** CL-070's `D_paired(2752, 11008) = 0.2398`. The 11008-vs-22016
disagreement rate `D` is **unknown and is itself a finding** (a collapsed D would be
direct evidence of convergence). At D = 0.24, n=200 needs ~835 cells; at D = 0.35, ~570.

**THE ADAPTIVE RULE — pre-registered, mechanical, no judgement at read time:**

1. Compute picks on a **first batch of 200 cells** (a prefix of one fixed shuffle,
   `order_seed = 20260729` — a prefix, not a re-draw, so extending never changes what was
   already computed).
2. Read the realized rate `D̂` off `picks/summary.json`. **Report it regardless of what
   follows** — it is a finding in its own right and the direct successor to CL-070's
   `D_paired`.
3. Set the total cell count `N_cells = min(ceil(200 / D̂), 2469)` (2469 = all non-solver
   cells in the bank) and continue with `--resume`.
4. **Budget guard:** if the projected total (picks + scoring) exceeds **8 h**, cut the
   scored-disagreement target to whatever 8 h buys, **state the reduced n and its implied
   power in the read-out**, and do not quietly under-run.
5. **Stopping is by CELL COUNT, never by looking at scores.** No score is inspected before
   the pick phase is complete. Scoring runs on the frozen disagreement set.

**Degenerate cases, decided in advance:**
- **D̂ < 0.08** ⇒ even the whole bank cannot reach n=200. Do NOT chase it: report the
  collapsed disagreement rate as the headline finding (it is strong evidence FOR
  convergence at 11008) and score whatever disagreements exist as a descriptive
  underpowered addendum, labelled as such.
- **D̂ > 0.45** ⇒ suspicious. Halt and check for a construction bug (a rate materially
  above CL-070's 4×-budget rate at a 2× budget step would be surprising) before scoring.

## 6. Inference — decided before the numbers exist

Records are **NOT independent**: cells are (root, salt) with up to 3 salts per root.
Every statistic clusters on `root_id`.

- **THE CITED ROW: cluster-robust sandwich se, clustered on root, G/(G−1) corrected.**
- **Conservative read: root-collapsed** (one unit-weighted mean per root).
- **Non-parametric confirmation:** 20 000 bootstrap resamples OF ROOTS (seed 20260729),
  reported for both the record-level and root-collapsed means.
- **Distribution-free:** sign test on records and on roots.
- Location robustness: median and 10 %-trimmed mean, so no single tail drives the call.
- **A naive i.i.d. z will not be cited.** The harness's own `summary.json` z is naive;
  as in the pilot, the read-out recomputes from the on-disk records.

**PRE-REGISTERED VERDICT MAP** (primary = cluster-robust, on the frozen n):

| outcome | verdict |
|---|---|
| CR z ≥ +2 **and** root-collapsed mean > 0 | **THERE IS ROOM ABOVE 11008.** The plateau is (at least partly) the ruler again, one rung up. Understanding only — no deploy consequence. |
| 95 % CI upper bound < +0.37 (i.e. the step is < half the 2752→11008 step) | **11008 IS AT / NEAR ITS KNEE on this instrument** — the first budget rung where deeper search stops buying real improvement. Report with §4's caveat: a weak judge biases toward this answer. |
| neither | **INCONCLUSIVE at this n.** Report the interval. Do not promote a direction. |
| CR z ≤ −2 | **THE WIDER PICK IS WORSE.** Would mean k16 is past the width optimum at 22016. Report as-is; do not rescue it. |

**The headline contrast** in every reading is this step's per-disagreement effect against
the pilot's **+0.7375 on the identical instrument**. Undiminished ⇒ the elo plateau is a
ruler artifact well past the champion. Collapsed toward 0 ⇒ the champion really does sit
at the knee. Report both this step's estimate AND the ratio to +0.7375.

**Pre-registered anti-fooling clauses:**
- Strata (phase, `h200_top2_q_gap` tercile) are **descriptive only**. The pilot's §3 splits
  were non-monotone noise; no stratum here may be promoted to a finding, and they will be
  printed with that sentence attached.
- **Winner's curse is expected.** This project has watched a screen shrink on extension
  four times (c=3 "+47", flywheel it16 "+88.7", C3-intra "+40.1", this pilot's own
  +1.91→+0.74). Any early-batch mean is a screen, not a verdict.
- The read-out is computed from the on-disk records by a separate analysis pass, not read
  off the harness summary.
- **No CL id, no `results.csv` row, no `PRODUCTION.yaml` change** unless the finding is
  later asserted as a claim — same terms the pilot closed on.

## 8. What would falsify / void this run

- **Agent-parity failure** on any verified cell ⇒ the prefix trick is invalid, the run is
  void, redo at 33024 sims/cell.
- **`crn_verified_all: false`** ⇒ the two arms were not paired for some position; those
  positions fail rather than silently entering unpaired (`--strict-crn`, default on).
- **A non-zero `n_positions_identical_afterstates`** ⇒ some "different" picks transpose to
  the same board; their zero deltas are identities, not evidence, and are reported
  separately.
- Any cell whose replay checksum mismatches is failed, never scored.
