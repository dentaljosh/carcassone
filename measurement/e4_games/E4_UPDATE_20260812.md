### The diagnosis is specific, and it is not a network fault

The device speaks adb: it sends a well-formed `STLS` packet, we answer `STLS`, and the TLS
handshake then fails with the device sending **`certificate_unknown`**. That alert direction
means **the phone does not have this host's adb key in its trusted list**. It is not a
firewall, not a wrong port, not tailscale, and not a stale adb server.

Contradicts the standing memory note "pairing keys persist — scan 30000-49999 for the connect
port": the port scan half still works, the *keys-persist* half has now failed. Most likely
cause is that Android's wireless-debugging pairing is scoped to the Wi-Fi network the phone
was paired on; a network change (or a "forget"/revoke) drops it. Either way the fix is
manual.

**To unblock (Joshua, on the phone):** Settings → Developer options → Wireless debugging →
**Pair device with pairing code**. That dialog shows a *different* port and a 6-digit code.
Then, from WSL:

```
adb pair 100.64.4.100:<PAIRING_PORT> <6-digit code>
adb connect 100.64.4.100:<CONNECT_PORT>       # 44749 as of tonight
adb shell run-as com.jishal.carcassonne ls files/games/
```

Nothing was deleted from the phone and nothing in this directory was modified.
